# Transaction results

What a transaction returns to your app. The names here are Halo.Core's; the .NET MAUI package presents the same results as .NET types (`ITransactionResult.OnlineRequest` and so on). See [Halo.Core for .NET MAUI](/docs/4.2/documentations/core/maui).

## Starting and cancelling

- **Start** a transaction with its configuration: amount, currency, transaction type, the [EMV tags](/docs/4.2/documentations/core/tags) you want back, and your terminal configuration. While it runs you receive UI messages to show your merchant; when it ends, you get exactly one result.
- **Starting fails immediately** only when there's no transaction to report on:

  | Reason | Meaning |
  | --- | --- |
  | `AlreadyRunning` | Another transaction is in progress. It carries on unaffected |
  | `InvalidConfig` | The terminal rejects the configuration (for example, a malformed CA public key) |

  Every other problem ends in a result.
- **Cancel** ends the running transaction with a `Cancelled` result. With nothing running, it does nothing.

## Results

A result is exactly one of these:

| Result | When | Carries |
| --- | --- | --- |
| `OnlineRequest` | The card was read and the transaction needs authorisation | Transaction id, device timestamp, plaintext EMV data, masked PAN, signed transaction data, signing chain, PIN continuation (when no PIN was taken yet) |
| `Declined` | The card or the kernel ended the transaction without going online | Reason, transaction id, device timestamp, plaintext EMV data, masked PAN (when a PAN was read) |
| `CardTapTimeOut` | No card was presented in time | Nothing |
| `Cancelled` | The transaction was cancelled | Reason |
| `PinCancelled` | The cardholder cancelled PIN entry | Nothing |
| `PinAttestationFailed` | The device's attestation for this PIN transaction failed | The attestation token |
| `Failed` | Anything else stopped the transaction | Error |

`PinAttestationFailed` deliberately carries no transaction data: a transaction whose attestation failed can't be submitted. Send the token to Halo Dot to find out why the attestation failed. See [Attestation tokens](/docs/4.2/documentations/core/backend/attestation-token).

### Fields

| Field | Type | Meaning |
| --- | --- | --- |
| Transaction id | UUID | Generated by Halo.Core when the transaction starts |
| Device timestamp | 64-bit integer | Unix seconds, device clock, when the result's data was produced |
| Plaintext EMV data | Bytes, plus a parsed list of tag/value pairs | The tags you listed in `plaintextTags`, minus sensitive ones. See [EMV tags](/docs/4.2/documentations/core/tags) |
| Masked PAN | String | See [Masked PAN](#masked-pan) |
| Signed transaction data | Bytes | Send it to your backend. See [Transaction data](/docs/4.2/documentations/core/backend/transaction-data) |
| Signing chain | List of bytes | DER certificates: the device signing certificate, then its issuer. The Halo Dot root isn't included |
| PIN continuation | Handle | See [PIN continuation](#pin-continuation) |

### Declined reasons

| Reason | Meaning |
| --- | --- |
| `Declined` | The card declined the transaction |
| `TryAgain` | The card asks to be presented again (for example, "see phone") |
| `CardReadFailed` | Communication with the card failed, or it was removed too early |
| `SelectNext` | The kernel asks for the card's next application to be selected |
| `TryAnotherCard` | The card's data or responses can't be used |
| `TryAnotherInterface` | The card needs chip or swipe (for example, over its contactless limit) |
| `NoSupportedApplication` | A payment card, but none of its applications is supported |
| `NotAPaymentCard` | Not a contactless payment card (for example, a transit or access card) |
| `MagstripeModeNotSupported` | The card offers only mag-stripe mode, which isn't supported |
| `EndApplication` | The kernel ended the transaction for no other listed reason |

### Cancelled reasons

| Reason | Meaning |
| --- | --- |
| `Caller` | Your app cancelled |
| `AppPaused` | The app went to the background mid-transaction |
| `SecurityError` | A security check ran during the transaction and failed |

### Errors

| Error | Meaning |
| --- | --- |
| `NotInitialized` | Halo.Core isn't initialised and registered |
| `RkiNotDone` | The device's keys haven't been loaded yet (remote key injection) |
| `AttestationInvalid` | The device's latest attestation is missing, out of date or failed |
| `SecurityCheckFailed` | A device security check failed at the start |
| `NfcDisabled` | NFC is off |
| `NfcLost` | NFC was turned off during the transaction |
| `PinFailed` | PIN capture failed (not cancelled by the cardholder) |
| `ProcessingError` | The transaction data couldn't be built |
| `TerminalError` | An internal error in the card reader |
| `AmountNotPresent` | The kernel reported no transaction amount |
| `ContinuationEnded` | A PIN continuation was used after it had ended |

## PIN continuation

For taking a PIN after the card read, without a second tap:

- **Dynamic currency conversion (DCC):** your calculation from the BIN and card currency calls for a PIN before you submit.
- **"PIN required" soft decline:** the issuer declines asking for a PIN, and you resubmit with one.

Every `OnlineRequest` taken without a PIN carries a PIN continuation:

| Action | Effect |
| --- | --- |
| Continue with PIN | Prompts for the PIN and returns a new result |
| Finish | Ends the continuation. Call it once the transaction is settled |

- The continuation lasts up to **10 minutes**. It also ends on finish, on cancel, or when you start a new transaction (which ends it rather than failing with `AlreadyRunning`).
- Continuing returns an ordinary `OnlineRequest` with the **same transaction id**, a PIN block, and no further continuation. Its transaction data is the first one's plus the PIN block, with a new device timestamp and attestation token. Amount and currency never change; DCC is entirely yours.
- Continuing can also return `PinCancelled`, `Failed(PinFailed)`, `PinAttestationFailed`, `Cancelled(Caller)` (cancelled during PIN entry), or `Failed(ContinuationEnded)` (the continuation had already ended).
- The PIN gets **one attempt**. Whatever continuing returns, the transaction ends there and the held card data is erased. Continuing again returns `Failed(ContinuationEnded)`.

## Masked PAN

The PAN with its middle digits replaced by `*`, present whenever a PAN was read, whether or not you listed it:

- 16 digits or more: first 8 and last 4 (`47617390****0119`)
- Shorter: first 6 and last 4 (`378282*****0005`)

The digits before the first `*` are the BIN. This follows PCI DSS (no more than the BIN and last four digits displayed) and the card brands' truncation rules.

## Protecting card data

An online request carries card data: the plaintext EMV data, the masked PAN and the signed transaction data.

:::warning
**Don't log or store transaction results.** Pass an online request to your backend for authorisation, then let it go.
:::

## Kernel outcomes

Each EMV kernel outcome maps to exactly one result. Error names are as in EMV Contactless Book C-2.

| Kernel outcome | Error indication | Result |
| --- | --- | --- |
| Declined | Any | `Declined(Declined)` |
| Try Again | L1 time-out, transmission or protocol error | `Declined(CardReadFailed)` |
| Try Again | None | `Declined(TryAgain)` |
| Select Next | Any | `Declined(SelectNext)` |
| Try Another Interface | Any | `Declined(TryAnotherInterface)` |
| End Application | L1 time-out, transmission or protocol error | `Declined(CardReadFailed)` |
| End Application | L2 EMPTY CANDIDATE LIST | `Declined(NoSupportedApplication)` |
| End Application | L2 NO PPSE | `Declined(NotAPaymentCard)` |
| End Application | L2 MAGSTRIPE NOT SUPPORTED | `Declined(MagstripeModeNotSupported)` |
| End Application | L2 PPSE FAULT, CARD DATA MISSING, CARD DATA ERROR, CAM FAILED, STATUS BYTES, PARSING ERROR, IDS errors | `Declined(TryAnotherCard)` |
| End Application | L2 MAX LIMIT EXCEEDED | `Declined(TryAnotherInterface)` |
| End Application | None | `Declined(EndApplication)` |
| Any | L2 TERMINAL DATA ERROR | `Failed(TerminalError)` |
| Any | L3 AMOUNT NOT PRESENT | `Failed(AmountNotPresent)` |
| Any | L3 TIME OUT | `CardTapTimeOut` |
| Any | L3 STOP | `Cancelled` |
